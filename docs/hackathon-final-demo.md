# Пятиминутная демонстрация

Сценарий UI проверен локально на изолированной синтетической БД. Финальный RunPod показ с реальным Qwen ещё не подтверждён. До него подготовьте минимум одну прошедшую grounding настоящую AI Evaluation, пример N/A, диапазон evidence и отдельный тестовый разговор для апелляции/нового чек-листа.

## 0:00–1:00

Войдите по защищённой HTTPS-ссылке. Dashboard: число реально оценённых разговоров, средний final score последней completed evaluation на разговор, языки/каналы. Перейдите в Диалоги, выберите заранее проверенный разговор. Покажите канал и оригинальные timestamps.

## 1:00–3:00

Откройте нужную историческую оценку. Назовите source и версию чек-листа. Покажите общий балл, ответы по критериям, N/A как исключение из применимого веса, отдельный critical flag. Нажмите quote/range/absence: подсветка переходит к настоящим message IDs. Объясните voice_transcript_only: интонация не анализировалась. Не утверждайте, что вывод модели достоверен лишь из-за валидного JSON.

## 3:00–4:00

На **тестовой** оценке нажмите «Оспорить оценку», введите причину. Откройте рассмотрение, выберите допустимый revised_answer, укажите reason. Покажите исходный и final score, сохранённое решение. Итог пересчитывает backend Scoring Engine; исходный результат не переписан.

## 4:00–5:00

Откройте отдельный демонстрационный checklist, создайте копию версии, измените критерий, сохраните веса100, сохраните и активируйте. Поставьте переоценку и откройте job: показать новую pinned version. Не ждать inference перед жюри, если измеренная latency превышает оставшееся время; честно показать queued/running и заранее завершённый настоящий результат.

## Перед показом

- API, provider и worker реально healthy; backup свежий; deployment SHA записан.
- Нужные evaluation/job IDs подготовлены локально, без публикации транскриптов/аудиоссылок.
- Данные разрешены для показа. Synthetic test/manual results явно названы синтетическими, не Qwen.
- Не переключать рабочий официальный checklist для smoke: использовать отдельный демонстрационный.
- Если provider offline, исторические результаты/UI доступны, но не заявлять realtime AI и готовность полного Stage4.
