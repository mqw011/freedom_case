# Контрольный набор: инструкция на 23-й час и стоп-код

**Текущий статус:** UI и весь сценарий импорта/очереди проверены на синтетических данных локально. Production URL и GPU на RunPod ещё не введены в эксплуатацию. Настоящий контрольный group_id не получен. До защиты должны быть закрыты SSH, storage, HTTPS/auth и реальные AI-проверки из README_STAGE4.

## До выдачи набора

1. Откройте защищённую HTTPS-ссылку, войдите учётными данными, полученными отдельным безопасным каналом.
2. В статусе сервисов убедитесь: backend online, provider available, worker online. Если worker offline — jobs могут ставиться в очередь, но завершаться не будут.
3. Откройте **Чек-листы**, проверьте нужную активную версию и сумму весов100.
4. Проверьте завершённую настоящую Evaluation, переход к evidence и сохранённые результаты после обновления страницы.
5. Организаторский URL должен быть настроен администратором только в server-side env. В UI нужен group_id, не подписанная ссылка. Право обработки контрольных данных на RunPod должно быть подтверждено.
6. Должны быть свежий backup и зафиксированные release/deployment SHA. Измеренный throughput должен быть известен; пока он не измерен, нельзя обещать обработку65 за час.

## Когда организаторы выдали group_id

1. Перейдите **Импорт данных**.
2. Введите ровно выданный `group_id`, нажмите импорт. Не угадывайте имя контрольной группы.
3. Дождитесь отчёта: received, inserted, skipped, warnings. Несовпадение received/ожиданий исследуйте, не меняя число вручную.
4. Откройте **Диалоги**, выберите импортированный dataset. Проверьте число диалогов, языки, открытие нескольких транскриптов.
5. Выберите весь dataset для пакетной оценки, проверьте версию чек-листа и количество выбранных записей; подтвердите постановку.
6. Откройте пакет в **AI задания**. Следите отдельно за queued/running/completed/failed/cancelled. Процент100 означает завершение обработки, включая ошибки, а не100% успешных оценок.
7. Открывайте completed evaluations, проверьте evidence, N/A и предупреждения human review. Failed job не является оценкой0.
8. Обработка продолжается в worker независимо от открытой вкладки; обновление браузера не запускает новый batch.

## Ошибки и повтор

- Импорт timeout/502/503: сначала откройте dataset list — импорт мог успеть завершиться. Повтор с тем же group_id идемпотентен и вернёт skipped для идентичных записей. Не создавать случайную новую группу для обхода ошибки.
- 409 import conflict: источник изменил существующий immutable transcript. Сохраните исходные данные и диагностируйте; не удаляйте набор.
- Provider/worker offline: восстановите сервис через администратора; не нажимайте запуск batch много раз.
- Failed inference: откройте job и attempts, прочтите safe error code. После исправления причины используйте Retry job или Retry failed у пакета. Не отменённые/завершённые jobs повторяются автоматически, а только подходящие failed.
- 524 от внешнего proxy не означает провал GPU. Jobs являются фоновыми: проверьте список/ID перед повторной постановкой.
- Evidence/semantic rejection: не обходите проверку. При повторном отказе оставьте failed и передайте на диагностику/ручной пересмотр. Нельзя выдавать ошибку за успешную AI-оценку.

## Если жюри заменило критерий

**Чек-листы → нужный checklist → Создать новую версию → изменить критерий/шкалу/N/A → веса100 → Сохранить → Активировать.** Затем выберите диалог и поставьте **новую переоценку**. В job details проверьте закреплённый checklist_version_id. Ранее созданные queued jobs сохраняют старую версию; активация её не меняет. Старые оценки и апелляции остаются в истории.

## Стоп-код на 24-м часу

Администратор заранее сохраняет последний проверенный Git SHA, deployment SHA, модель+digest, безопасные настройки, migration revision и backup. Код на сервере должен совпадать с отправленным в GitHub. Проверить SHA можно командой `git -C "$CQA_RELEASE" rev-parse HEAD`; эта административная проверка не требует изменения кода.

После freeze **не выполнять git pull, не редактировать Python/JS, программные prompts и deployment source**. Разрешённые сценарием операции остаются через UI: импорт, batch/retry/cancel, просмотр, новые версии чек-листа/активация, переоценка, апелляции и решения. При restart запускать тот же закреплённый release. Отправку ссылки организаторам выполняет владелец; автоматическая рассылка не настроена.
