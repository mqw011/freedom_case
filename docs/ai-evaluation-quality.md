# Качество AI-оценки и протокол измерений

## Эталонные данные

`app/ai/benchmark/cases.py` содержит 9 независимо составленных синтетических диалогов: по 3 RU, KZ, EN. Ответы заданы вручную по официальной рубрике, а не скопированы из Qwen. Покрываются приветствие/завершение, N/A, неполный ответ, идентификация с системным подтверждением и без него, частное платное предложение, bot/system и prompt injection.

Это небольшой диагностический набор, составленный при реализации. Независимая проверка банковским QA-экспертом и носителем KZ ещё необходима. Метки не являются универсальной истиной для реальных диалогов. В частности, фактические тарифы/правила компании нельзя проверить по одному транскрипту; для них нужен источник знаний и человеческий контроль.

## Метрики

Команда `python -m app.ai.benchmark` выполняет настоящий LLMEvaluator, включая repair и семантический audit, без сохранения тестовых результатов в DEV.

- Valid JSON rate: валидные JSON-ответы / HTTP generation requests; транспортные retries входят в знаменатель, отменённые запросы могут иметь неизвестный token usage.
- Schema validation rate: прошедшие Pydantic оценки / assessment attempts. Служебные semantic/chunk DTO не входят в этот знаменатель.
- Criterion completion rate: полный уникальный набор критериев / assessment attempts.
- Evidence validity rate: прошедшие структурный grounding / полные ответы.
- Criterion agreement: совпавшие ответы / 8 критериев успешных кейсов.
- N/A agreement: совпадение применимости по 4 допускающим N/A критериям, включая отрицательное совпадение.
- Critical precision/recall: TP/(TP+FP), TP/(TP+FN), null при пустом знаменателе.
- Score MAE: средняя абсолютная разница Decimal итогов (агрегат отображается числом).
- Latency: wall clock на весь case, включая repair/audit.
- Отдельные sample/completed/agreement и failures по RU/KZ/EN.

Agreement и MAE считаются **условно по успешным кейсам**, рядом обязательно показывается число failures. При малой выборке precision/recall нестабильны. Структурная валидность и семантическая правильность различаются; self-audit одной моделью не заменяет независимого эксперта.

## Реальные DEV данные

Оценки создаются только настоящим inference и хранятся в частной SQLite.
DEV перенесён на защищённый RunPod после явного разрешения владельца данных. В публичном отчёте допустимы агрегаты, internal IDs, длительности и баллы; запрещены тексты, prompts, аудио URL и подписанная ссылка организаторов.

При проверке 2026-11-07 модель `qwen3:4b` (Q4_K_M, 2.5 GB), Ollama 0.13.5 первоначально запустилась на GTX 1660 Ti Mobile, 6144 MiB VRAM. При context=16384 Ollama сообщала 100% GPU и около 5.4 GB модели/контекста; nvidia-smi показывал около 4972 MiB. Первый RU pipeline сохранил настоящий результат после исправления evidence (69.067 секунды).

Во время последующей нагрузки GPU достигла 97°C, затем nvidia-smi вернул `Unknown Error / No devices were found`. Журнал ядра подтвердил NVIDIA Xid 79 («GPU has fallen off the bus») и Xid 154 с recovery action OS Reboot. Причина на уровне аппаратуры/драйвера не установлена; утверждать, что сбой вызван только температурой, нельзя. Система и драйверы не менялись. GPU inference остановлен; Ollama перезапущена на CPU с `CUDA_VISIBLE_DEVICES=-1`, та же модель успешно ответила HTTP 200. Для CPU использованы context=24576, timeout=600, output=2048, concurrency=1. Прерванные/невалидные попытки сохранены в истории, фиктивных успешных результатов нет.

## Ограничения

- Маленькая локальная модель может ошибаться в смысле даже с точными цитатами. Недостаточно проверить только JSON.
- KZ измеряется отдельно; поддержка Unicode не является доказательством понимания казахского языка.
- Неизвестная фактическая корректность финансовых рекомендаций требует human review. Это не основание произвольно ставить N/A.
- Голосовые диалоги оцениваются только по тексту; интонация/дикция не анализируются.
- Полное чтение всех окон гарантируется структурно, но модель может пропустить значение реплики. Контекстное переполнение отклоняется, а не скрывается.
- GPU на проверяемой машине стала недоступна во время теста. Для дальнейшего GPU запуска нужна отдельная диагностика окружения; CPU путь не зависит от CUDA.

## DEV inference: фактическое состояние

Создано 9 jobs для 5 выбранных диалогов (включая отдельные CPU-повторные постановки). Состояние: 1 completed, 1 failed, 3 cancelled, 4 queued. Worker остановлен после аппаратного сбоя и bounded CPU проверки; очередь сохраняется для продолжения.

Выполнено 6 попыток job: 1 успешная и 5 неуспешных/прерванных. Это число запусков pipeline, не число HTTP-запросов. Старые диагностические записи раннего transport недосчитывали HTTP retries/прерванные запросы; счётчик исправлен и протестирован, но исторические записи не переписывались. Поэтому точное суммарное число ранних HTTP inference-вызовов не заявляется.

- RU: conversation internal ID 25, Evaluation 1, 8 критериев, initial/final score `10.00`, critical_violation=false, 69.067 секунды на успешную попытку с одним repair. Это результат модели, не экспертный эталон.
- KZ: GPU-попытка отклонена после трёх невалидных evidence-ответов; CPU-попытка завершилась provider_timeout за 600.048 секунды. Успешной оценки нет.
- EN: попытка прервана при отказе GPU; Evaluation не сохранена.
- Длинный разговор (115 реплик, voice call): начат, прерван при отказе GPU; Evaluation не сохранена.
- Второй voice call (45 реплик): поставлен в очередь, inference не завершался.

Всего сохранена 1 настоящая AI Evaluation; средний балл по ней `10.00` не характеризует качество операторов всего DEV. Средняя длительность всех 6 попыток, включая сбои/остановки, около 229.20 секунды; успешной единственной — 69.067 секунды.

Короткий диагностический CPU запрос подтвердил HTTP 200; полный pipeline на CPU в заданном бюджете не подтверждён. Потоковая диагностика синтетического prompt за 120 секунд не получила ни одного фрагмента. Увеличение timeout само по себе не является подтверждением работоспособности.

ступени, N/A и Scoring Engine не ослаблялись. Программная формула не менялась.

score100.00, critical=false,107.935s,2provider calls,0repairs,6294input/3107output tokens.
Это модельная оценка, не независимый экспертный эталон. Она открыта и проверена браузером:
