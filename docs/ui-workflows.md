# Пользовательские сценарии

## Контрольный набор на 23-м часу

1. Открыть **Импорт данных**, ввести выданный `group_id`, нажать импорт. Адрес организаторов уже настроен на backend; секретный URL в браузер не вводится.
2. Проверить received/inserted/skipped и warnings. Повторный идентичный импорт пропускается; конфликт изменённого содержимого требует проверки, UI не перезаписывает записи.
3. Открыть набор из отчёта. Выбрать все найденные или отдельные разговоры; нажать **Оценить выбранные**.
4. Выбрать чек-лист/версию. При недоступном provider/worker задания остаются queued. Перейти в пакет и наблюдать реальные completed/failed/cancelled.
5. Failed можно повторить из карточки job или кнопкой «Повторить только failed» у пакета. Queued можно отменить; running требует подтверждения отмены worker.
6. Для JSON выбрать файл формата организаторов в том же разделе. Ошибки схемы/сети показываются рядом с формой.

## Оценка и evidence

Открыть диалог → выбрать оценку из истории → раскрыть критерий → нажать цитату/диапазон/отсутствующее действие. Транскрипт прокручивается к настоящему ID, реплика получает focus и подсветку. N/A имеет собственное условие и не отображается как ноль. Initial/final и critical flag видны отдельно. У звонка аудио загружается только по действию пользователя; если источник недоступен, остаётся ссылка на запись. Текст звонка не позволяет утверждать оценку интонации.

## Апелляция

«Оспорить оценку» в нужном критерии → комментарий → подать → карточка апелляции. Проверяющий видит исходное обоснование, evidence и контекст. Выбирает подтвердить либо изменить, допустимый ответ и обязательную причину. Backend сохраняет решение и пересчитывает final. История и исходный ответ остаются доступными. Закрытая апелляция больше не показывает форму решения; конкурентное решение другого проверяющего возвращает 409 и обновляет данные.

## Изменение критериев без изменения кода

Чек-листы → выбрать → **Создать новую версию**. Изменить формулировки, секции, шкалу/описания ступеней, N/A, веса; добавить/удалить/переместить критерии. Total Weight обновляется точно. Сохранить новую версию → активировать с подтверждением → выбрать диалоги для переоценки. Новое job закрепит новый version ID; старые evaluations и критерии остаются прежними.

Сумма не 100 допускается только у сохранённой неактивной версии. Дубли кодов/порядка, неправильные шкалы, отрицательные веса и некорректный N/A блокируют сохранение. Flag имеет вес 0, ответы yes/no и не допускает N/A.

## Пятиминутная защита

Использовать отдельный синтетический sandbox из README_STAGE3; баннер не скрывать.

- **0:00–1:00** — Dashboard, все 65 тестовых диалогов, поиск/язык/канал, первый разговор.
- **1:00–3:00** — тестовая ручная оценка 81.88, все восемь критериев, N/A, цитата, range, конец длинного транскрипта. Явно назвать источник `test`, не Qwen.
- **3:00–4:00** — апелляция по завершению, revised=yes с причиной, сохранение: initial 81.88 / final 88.13, история.
- **4:00–5:00** — новая версия чек-листа, изменение формулировки/весов, сохранение/активация, постановка нового задания с новым version ID. Worker offline означает queued, а не выполненную оценку.

Историческую настоящую AI-оценку в рабочей базе можно открывать локально, но не публиковать скриншоты реальных клиентских диалогов. Полная проверка Qwen будет завершаться отдельно на доступной GPU в Stage 4.
