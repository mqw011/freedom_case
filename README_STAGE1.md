# Stage 1 — Implementation Report

Проверено локально на CachyOS 7 ноября 2026 года. Рабочие команды и настройка — в [README](README.md).

## Статус реализации

**Complete для объёма Stage 1.** Реализованы FastAPI backend, SQLite/SQLAlchemy, две Alembic-миграции, начальный чек-лист, API/file import, версии, Scoring Engine, оценки, апелляции и React foundation. Настоящий DEV endpoint не предоставлен; импорт 65 реальных диалогов не заявляется.

## Реализованные компоненты

- Backend: `/api`, Pydantic request/response DTO, OpenAPI/Swagger, единый error envelope, JSON logging, CORS и конфигурация окружения.
- Database: 11 прикладных таблиц, FK/unique/indexes, UTC, точное хранение Decimal, optimistic revision для решений и активации.
- Migrations: чистая схема + замороженный исходный seed из восьми критериев. Идемпотентная seed CLI не перезаписывает пользовательские версии.
- Dataset Import: настроенный HTTP endpoint с timeout/ограничением размера/без redirects, multipart JSON, RU/KZ/EN, порядок/исходные timestamp, audio_url, атомарность и дедупликация.
- Checklists: создание, просмотр, полные неизменяемые версии, произвольные секции/критерии/шкалы, активация при сумме весов 100.
- Scoring Engine: Decimal, точные ступени, N/A, нормализация, ROUND_HALF_UP, null при нулевом применимом весе, отдельный critical flag.
- Evaluations: manual/test endpoint, исходные/финальные баллы, структурные проверки evidence, внутренний DTO для будущего AI без подключения LLM.
- Appeals: pending/upheld/revised, обязательная причина, до/после, повторные апелляции с сохранением истории, автоматический пересчёт.
- Frontend Foundation: React/Vite/JavaScript, Fetch API, переменная backend URL, пять подготовленных маршрутов, состояния соединения, адаптивная минимальная страница.

## Проверки

- **153 теста пройдены, 0 провалено.** Полный набор выполнен также в отдельном чистом venv.
- Ruff: успешно для backend и вспомогательного скрипта.
- Alembic: upgrade с нуля, downgrade/upgrade на одноразовой БД, проверка соответствия модели миграциям.
- Frontend: `npm install`, `npm run lint`, `npm run build` успешны; `npm audit` сообщает 0 уязвимостей в закреплённом наборе зависимостей.
- Отдельный процесс Uvicorn: `/api/health`, `/docs`, `/openapi.json` → 200.
- HTTP smoke: импорт/повторный импорт → транскрипт → активный чек-лист → оценка 81.88 → новая версия/активация → старая оценка неизменна → апелляция → 88.13 с сохранённым initial_score=81.88.
- Chromium: пять маршрутов, online/offline health, ширины 1440 и 390 px, отсутствие горизонтального переполнения на мобильном экране и ошибок JavaScript.
- Автотесты внешнего импорта используют настоящий локальный mock HTTP-сервер; API организаторов не вызывается.
- В Git не включаются `.env`, SQLite-файлы, виртуальные окружения, node_modules и реальные записи звонков.

У инструментов есть upstream notices: Starlette сообщает о будущем отказе TestClient от HTTPX, а npm отмечает окончание поддержки ESLint 9.39.5. ESLint закреплён на этой версии, рекомендованной `npm audit`, чтобы исключить обнаруженную у ESLint 10 цепочку уязвимого minimatch. Проверки проходят; это предупреждения зависимостей, не скрытые провалы тестов. Следующее обновление toolchain должно повторить lint/build/audit и тесты.

## Допущения и ограничения

1. Уникальность внешнего conversation_id ограничена group_id; пересечения DEV/контрольного набора не уничтожают записи.
2. Изменённое содержимое уже импортированного диалога возвращает 409; автоматического обновления транскрипта с существующими оценками нет.
3. Несовпадение объявленного total_records даёт предупреждение, а фактический массив сохраняется целиком. Пустой корректный набор разрешён.
4. Начальные/финальные Decimal значения API — строки. Raw timestamps остаются оригинальными строками.
5. Ручные результаты требуют объяснения; evidence необязателен, но все переданные ссылки и цитаты проверяются. Семантический анализ отсутствующего действия относится к Stage 2.
6. Сохранённые версии не редактируются. Неактивную версию с несогласованной суммой можно сохранить, но нельзя активировать или оценивать по ней.
7. Рабочие страницы, AI/STT/очередь, Docker/RunPod/HTTPS относятся к следующим этапам. Реальные DEV данные отсутствуют. PostgreSQL не развёртывался и не тестировался.

## Готовность к Stage 2

`AIEvaluator` принимает `EvaluationContext`, возвращает `StructuredEvaluation`. JSON Schema экспортируется из Pydantic. Настройки Ollama/OpenAI-compatible endpoint уже предусмотрены. AI-адаптер передаёт `EvaluationSubmission(source="ai")` в `EvaluationService`, который выполняет EvidenceValidator → Scoring Engine → persist. Этот путь проверен отдельным тестом с переданными структурированными ответами; никакой фиктивной inference-реализации нет.
